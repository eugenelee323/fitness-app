# 12週增肌

單一使用者、繁體中文、手機優先的離線 PWA。已完成階段 0–3：PWA、訓練與備份、固定規則引擎、每週報告、建議確認、下週課表產生及飲食紀錄。

## 本機使用

需要 Node.js 24 與 pnpm 11.25.0。在專案目錄執行：

```sh
pnpm install
pnpm dev
```

開啟終端機顯示的 `http://127.0.0.1:5173/fitness-app/`。若要驗收離線功能，使用正式建置預覽：

```sh
pnpm build
pnpm preview --port 4173 --strictPort
```

瀏覽器開啟 `http://127.0.0.1:4173/fitness-app/`。首次連線載入完成後，service worker 會快取應用程式；之後可離線重新開啟。開發模式不註冊 service worker。本機伺服器只綁定電腦的 127.0.0.1；手機請使用部署後的 HTTPS 網址。

## 匯入與階段 0 驗收

1. 首次開啟會顯示「匯入個人資料」。選擇本機 `my-data.json`，檢查各表筆數，再按「確認匯入」。也可以略過後從設定頁匯入。
2. 前往「訓練」，展開週次，確認 12 週的菜單、階段、減量週與中英文動作名稱。第 2 週套用規格的目標重量，其餘週重量保留為試重／待確認；不預先套用未接受的建議。
3. 減量週組數減半，奇數組向上取整；目標 RIR 3。第 4 週的延後減量判斷將於階段 2 實作。
4. 前往「設定」，確認已匯入的個人資料、營養目標、身體數據與紀錄筆數。重新整理後資料仍保留。
5. 匯入只接受第 13 節個人資料的六張表，支援 `week_no`、`ref`、`session_ref`、`exercise_code`，會對應內建 UUID。確認前不寫入；寫入失敗整批回復。同日營養／身體數據及同次訓練更新，其他紀錄保留。
6. 首次載入完成後，以瀏覽器開發工具的離線模式重新整理，確認首頁與各 HashRouter 路徑可開啟。實體手機安裝仍需在部署後驗收。

訓練紀錄與完整備份已於階段 1 實作。飲食與分析保留空白狀態；每週結算與建議確認已於階段 2 完成；飲食整合與圖表待後續階段加入。

5. iPhone：Safari 開啟部署網址 → 分享 → 加入主畫面。
6. Android：Chrome 開啟部署網址 → 選單 → 安裝應用程式／加到主畫面。

GitHub repository：[eugenelee323/fitness-app](https://github.com/eugenelee323/fitness-app)。推送後仍需在 Settings → Pages 選擇 GitHub Actions，並確認部署工作流程成功。

## 資料與開發規範

- 沒有後端、登入、API 金鑰或執行期外部服務呼叫；所有資產由本站提供。
- 個人資料只來自使用者選取的檔案；不會讀取專案中的 `my-data.json` 並打包。
- 第 11 節 SQL 共 17 張應用資料表，移除 `auth.users`、`user_id`；單人資料仍以 UUID 主鍵儲存，替代動作使用複合主鍵。
- 資料結構定義於 `src/db/schema.ts`；Dexie 版本 2 新增週次排序索引，保留版本 1 既有資料。後續異動必須使用新版本升級，不可刪庫重建。
- 動作與課表位於 `src/seed/`，交易式初始化，重複啟動不會重複寫入。
- 重量、組數、熱量、容量計算放在 `src/lib/rules/` 並逐一測試；未來建議文字放在 `src/lib/explain/` 固定範本。
- 啟動時呼叫 `navigator.storage.persist()`；是否授權由瀏覽器決定。
- 資料儲存在目前瀏覽器與來源網址的 IndexedDB；不同電腦、瀏覽器或網址不會共享資料。

交付前必須執行：

```sh
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

技術參考：[Tailwind 的 Vite 安裝方式](https://tailwindcss.com/docs/installation/using-vite)、[Vite PWA 官方文件](https://github.com/vite-pwa/vite-plugin-pwa/blob/main/docs/guide/index.md)。

## 階段 1：訓練紀錄

- 首頁顯示本週菜單、減量週、完成率與超過 7 天的備份提醒。不綁定固定星期；推日完成後提示拉日，開始前可自行改選。
- 「訓練」選週次與推／拉日後開始。目標重量優先，沒有目標時沿用上次同動作重量；首次動作須試重，徒手填掛重 0。次數與 RIR 已預填；正常記組選 RIR、按完成只需兩次點擊。
- 每個動作顯示中文、英文、目標、休息與上次實績。單手左右分別記錄。替換僅影響本次未完成組，保留原實績，寫入變更歷史，未來課表不變。
- 每次輸入、完成組、替換、休息計時與結束表單都儲存至 IndexedDB。看到「所有變更已儲存」後可離開；重新開啟「訓練」接續同一筆。倒數依結束時間計算，切到背景後不會以計時器 tick 累積誤差。
- 結束時填疲勞、睡眠；疼痛可新增多個部位，也可略過。未做完仍可確認後以部分完成儲存。徒手／輔助動作須填本次體重以計算容量。
- 歷史可查看各組明細、總容量、肌群有效組數與疼痛。刪除需明確確認，會一併移除該次組數、疼痛與草稿。
- 完整備份包含全部 20 張表（原 17 張表與草稿、匯入對應、本機設定）。匯入先驗證每列、唯一性與外鍵、顯示筆數；勾選確認後整庫取代，失敗會整批回復。舊版 17 表完整備份仍可還原。
- `my-data.json` 使用合併模式，依來源 ref／id 建立獨立對應；同日自行記錄的訓練不會被取代。再次匯入同來源會更新該初始紀錄，不刪除額外組數或其他紀錄。預覽後有新增資料，確認時仍會重新對應。
- Dexie 版本 3 新增狀態資料表，保留版本 1／2 的資料。完整備份與個人資料仍只存在裝置或使用者自行下載的檔案。

### 手機驗收步驟

1. 等待 GitHub Actions 部署成功，在主畫面 App 連線開啟；若看到新版提示，按「重新載入更新」。
2. 到訓練選第 2 週推日，檢查臥推預填目標。選 RIR 再按「完成這組」，確認休息倒數出現，可暫停、繼續、略過。
3. 修改下一組次數，等待顯示已儲存後關閉 App，再開啟。確認完成組數、未完成輸入與倒數仍在。
4. 滑到單手側平舉，確認左右各一列；替換其他動作，確認替代動作顯示中英文名稱，原已完成組未消失。
5. 結束訓練填疲勞與睡眠，可新增疼痛部位；儲存後檢查容量、有效組數與歷史明細。
6. 設定 → 匯出完整備份，確認在 iPhone「檔案」找到 JSON。再匯入同檔，檢查各表筆數，勾選後確認還原，核對歷史與進行中草稿一致。
7. 先新增自己的訓練，再選 `my-data.json` 合併，核對先前訓練仍保留。
8. 刪除測試訓練時先按取消，確認紀錄仍在；再次刪除並確認，核對歷史已移除。

測試含負重類型、左右合計、有效組數、規格加重／BMR 案例、草稿恢復、匯入合併、完整備份一致性與交易回復。本機若有 `my-data.json`，額外驗證原始推日容量 9,447 kg；CI 沒有私有檔時會明確略過該案例，合成容量測試仍執行。

## 階段 2：規則引擎與每週分析

- 固定以 2026-11-09（週一）為第 1 週，所有結算時點使用 Asia/Taipei。每週日 21:00 後開啟／回到 App 時，自動結算尚未結算的週；進行中訓練所在週先等待結束。可在設定或分析頁手動選週結算。
- 週報包含完成率、每肌群有效組數（10–20 組參考區間）、容量、上週及上次同 A／B 菜單對照、e1RM 進退步、停滯週次觀測及連續持平／退步次數、平均疲勞與睡眠、疼痛／刺痛。
- 單手左右容量分別加總、有效組數按同組編號合計；肌群容量只歸主要肌群，避免重複加計。缺體重時相關容量／e1RM 標示缺資料；沒有對照或分母為 0 不計百分比。缺疲勞／睡眠不當作 0，也不憑空判定疲勞。
- 停滯以同動作連續 2 次持平／退步判斷；組數規則另使用有同動作紀錄的週次觀測。主動作連續兩週退步的減量條件要求相鄰週，不把未訓練的空白週算成退步。
- 下週建議逐條接受、拒絕或修改。這些操作只儲存決定，不改課表；全部處理後按「產生下週課表」，才用單一交易寫入課表、減量安排與 `plan_changes`。拒絕的項目保留原課表，產生後提醒備份。
- 數值修改仍檢查一次只改重量或組數、單次每肌群 12 組、單日估計 120 分鐘，以及一天最多一個壓下背動作。時間估計採每下 4 秒加計每組休息；單手左右各計一份。停止動作若無對應替代動作，會先標示暫停並從訓練頁排除。
- 腰部疼痛 ≥ 1 分改用俯臥腿彎舉；一般相關疼痛 ≥ 4 分或刺痛先停止／替代，連續兩次高痛或刺痛會依固定文字提示就醫。可在結束訓練的疼痛欄勾選刺痛。
- 預定減量週只有三個主動作都進步、疲勞 ≤ 5、無疼痛才提出延後；原定週次會保存，最多延 2 週且不超過第 12 週。可把延後提案修改成照原定週次減量。減量組數減半（奇數向上取整）、重量不變、RIR 3；結束後回到保留的正常組數與重量，除非又觸發緊急減量條件。
- 結算後若訓練資料或目標課表已變動，需重新結算；目標週已開始訓練時，不再改動該週課表。未套用前重新結算會重建建議並清除該次決定，介面會先確認；已產生課表後重新結算只更新報告、保留已套用歷史，不重複加重。
- Dexie 版本 4 保存正常組數、RIR 與減量原定週次，升級保留舊資料。第 12 節全數基礎公式保留純函式；建議原因使用 `src/lib/explain/` 固定繁中文範本。
- `pnpm test` 預設執行 V8 覆蓋率檢查，每個 `src/lib/rules/` 程式檔的行數、陳述、函式及分支皆須 ≥ 90%。報告輸出至忽略的 `coverage/`。本機私有檔案例不會複製資料進 repo；CI 無私有檔時使用合成容量案例並略過該私有檔測試。

### 階段 2 手機驗收

1. 等 Actions 部署成功，連線開啟主畫面 App，按新版更新提示。先在設定匯出完整備份。
2. 完成一筆訓練，再到「分析」或設定的「每週結算」，選對應週次，按結算。當週未結束也可手動結算；新增紀錄後請重新結算。
3. 查看週報的完成率、肌群組數、容量比較、動作進步與疼痛，按「查看下週建議」。
4. 接受一條建議後切回 12 週計畫，確認尚未改變。回到建議頁，逐條接受／拒絕／修改；待確認未歸零時不可產生課表。
5. 全部處理後按「產生下週課表」，確認課表更新、顯示備份提醒；重開 App 不會再次加重。再匯出備份。
6. 在已有報告的週次按重新結算，檢查確認提示。未套用的決定需重新處理；已產生課表的報告只更新數據。
7. 自動觸發與兩週延後上限已以固定台北時間及多週資料測試；不需要修改手機時鐘來測試。

## 階段 3：飲食紀錄

- 飲食頁可切換日期，固定顯示早餐、午餐、晚餐、點心；各食物、每餐與全天合計包含公克、熱量、蛋白質、碳水、脂肪，估算值標「估」。首頁與飲食頁共用每日進度與 dailyStatus 達標判定；台北 21:00 後當日蛋白質不足 30 g 以上時顯示固定補充提示。
- 可手動新增多項食物、編輯整餐（日期、餐別、名稱、份量與全部營養素）、確認後刪除。改公克數即時按比例重算；比例保留原始基準，避免反覆編輯的四捨五入累積。可存成常用餐點，一鍵帶入所選日期，再依需要編輯。
- 第 13 節貼上格式支援空白、全形符號與冒號、ml；預覽錯誤行標紅並可直接修正，全部有效才可核對與儲存。貼上來源固定保留 is_estimate=true。
- 每週報告包含餐別紀錄完整率、有紀錄日平均蛋白質、達標天數、7 日平均體重及腰圍變化。同日同餐別只計一次，訓練日預計 4 餐、休息日 3 餐，不要求照片；當週只計已到日期。體重平均至少需每週 4 天資料，不把缺紀錄當作 0。體重與腰圍輸入留待階段 4，目前可用匯入資料提供。
- weeklyKcalDelta 產生的熱量建議納入既有「每週結算 → 接受／拒絕／修改 → 產生下週課表並套用營養建議」。逐條接受只記決定；最後才新增 nutrition_targets，保留舊目標並寫 plan_changes。套用後不可重複；失敗整個交易回復，完成提醒備份。即使沒有訓練紀錄，符合條件的飲食建議仍可確認。
- 每次調整最多 ±150 kcal；保留蛋白質與脂肪，熱量差額除以 4 換成碳水增減量（整克四捨五入）。紀錄完整率 <70%、平均蛋白質 <130 g、調整未滿 2 週、已有未生效調整時不再調整。預定下週一生效，逾期確認改為當日，避免回寫歷史。
- Dexie 版本 5 增加常用餐點與營養目標追蹤索引，保留舊資料。完整備份包含 21 張表，舊備份沒有常用餐點時視為空表。my-data.json 與備份檔持續忽略。

### 階段 3 手機驗收

1. 在 GitHub Pages 開啟 App，看到更新提示後按「重新載入更新」。先在設定匯出完整備份。
2. 飲食 → 貼上 Claude 估算，貼第 13 節範例；確認解析 2 項。加一行錯誤文字，確認標紅且不能繼續，修正後按「核對各項目」。
3. 把便當由 550 g 改為 275 g，確認 820 kcal 變成 410 kcal，其他營養素減半；儲存後兩項都有「估」。
4. 按「編輯」修改名稱、餐別或營養素；再存成常用餐點。切到另一日一鍵帶入，確認日期與每餐／全天合計。
5. 關閉再開 App，檢查餐點仍在；匯出完整備份再還原，核對餐點、常用與歷史營養目標一致。
6. 分析 → 結算有飲食資料的週次，查看完整率與達標天數；若符合熱量調整條件，在下週建議逐條處理後才按最後套用。接受單條後，營養目標尚不應改變。
7. 晚上 21:00 後當日蛋白質仍差至少 30 g 時，首頁與飲食頁顯示補充提示。時間邊界、熱量調整與歷史保留另有自動測試，不需修改手機時鐘。

## 階段 4：身體數據、趨勢圖與 CSV

- 首頁可快速記錄當日體重；身體數據頁可依日期新增、更新、刪除體重與選填腰圍。同日更新保留紀錄 id 與未修改的體脂；首頁快速輸入保留原腰圍。刪除身體數據不改動訓練當次儲存的體重。
- 共用 bodySummary 計算連續 7 日平均（至少 4 筆）、與前一個 7 日視窗的差值及每週 +0.15～0.25 kg 目標範圍。每週 nutritionWeek 與 weeklyKcalDelta 使用相同的平均週變化及四週腰圍差值，避免看單日增減。腰圍採當前 7 日視窗與四週前視窗各自最後一筆；任一缺資料不推算。
- 分析頁加入 Recharts：可切換肌群的有效組數長條圖（10–20 組區間）、推日／拉日／合計容量與上週變化、三個主動作及其他動作 e1RM、每日體重點與 7 日平均線、腰圍、最近四週熱量與蛋白質達標曲線及日曆。每張圖提供數值表，空資料提示、缺資料留空，不補 0；訓練草稿不納入圖表。
- 圖表由同一筆 IndexedDB 實際紀錄即時重算，不依賴過期週報。圖表分塊載入，手機直向可讀。容量圖註明「容量增加不等於肌肉增加」。
- 設定 → 匯出 CSV ZIP，每張資料表一個 CSV，包含空表標頭、UTF-8 BOM、CRLF、雙引號轉義與巢狀 JSON；可在 Excel 顯示中文。文字公式前加單引號以文字顯示。CSV 用於分析，完整還原仍使用 JSON；匯出 CSV 不會重設完整備份時間。
- 沿用既有 body_metrics 結構與唯一日期索引，沒有新增或清空資料表；不需要 Dexie 結構升級。ZIP 在裝置上使用 fflate 打包，無上傳、後端或 API 金鑰。

### 階段 4 手機驗收

1. 開啟主畫面 App，看到更新提示後重新載入，先匯出完整 JSON 備份。
2. 首頁輸入今日體重，進「體重與腰圍紀錄」補過去日期及選填腰圍；改同一天的體重確認沒有重複紀錄，首頁快速改體重時腰圍仍保留。
3. 在近 7 日記滿 4 筆後核對平均；不足 4 筆顯示資料不足。有前一週至少 4 筆時顯示週差值與增重範圍判定。
4. 到分析切換肌群、主動作／其他動作，展開「查看圖表數值」比對訓練歷史。選擇四週結束日期，核對體重、腰圍與飲食日曆；空日期應顯示提示而非 0。
5. 修改或刪除一筆身體數據，確認圖表即時更新；已結算但未套用的建議需重新結算，才會使用更新後的週平均與腰圍。
6. 設定 → 匯出 CSV ZIP，在 iPhone「檔案」解壓縮，或傳到電腦用 Excel 開啟 body_metrics.csv、meal_items.csv，確認中文及數值正確。需要還原時仍使用 JSON 備份。
